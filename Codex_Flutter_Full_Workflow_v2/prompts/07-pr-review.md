# 07 — PR review + CodeRabbit gate

Use `$flutter-architecture-guard` and `$codex-efficient-workflow`.
PR/BRANCH: [BRANCH OR PR]
TARGET TASK: [FEATURE/TASK ID]
BASELINE/BASE BRANCH: [BRANCH]
KNOWN TEST/SCREENSHOT EVIDENCE: [PATHS OR COMMAND OUTPUT]

Read only task-relevant diff and approved acceptance criteria. Perform a review organized around: correctness, regression risks, architecture boundaries, privacy/auth/offline data safety, missing tests, visual evidence and unrelated changes. Report actionable findings with exact file/line references and severity as normal engineering triage (not an overall score).

If a CodeRabbit PR review has **actually been run**, inspect its real findings and respond to substantive issues with scoped fixes/tests. Otherwise mark `CodeRabbit: PENDING` and provide steps or PR checklist for the user to initiate it; do not claim it was executed. Do not auto-merge, deploy or change remote services.

Output: findings first, checks/evidence, CodeRabbit status, screenshot human-approval status and a focused follow-up task. If no high-confidence findings, explicitly mention testing gaps or unverifiable claims.
